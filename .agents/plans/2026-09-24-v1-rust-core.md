# intl-ai v1: Rust core, single binary, tiered checks

**Status:** draft 2026-09-24. Modeled on cauce v3 (`.agents/plans/2026-09-21-v3-rust-core.md` in espetro/cauce), whose plugin ladder and rebuild lessons transfer directly.

## 1. Why

The TS packages cannot serve mobile/desktop teams without Node on the build machine, and checks are hardcoded: a dialect check needed an external script, and Jev has no integration path. A single static Rust binary removes the Node dependency and makes every extension point explicit.

Owner decisions already taken:

- Language: Rust. UniFFI is Rust-only (Kotlin/Swift/Python bindings generated, not hand-written); ICU validation gets real parsers (section 5); `rquickjs` is the deferred sandbox; cauce v3 is the second in-org Rust core so patterns and CI transfer. Go/Zig comparison: section 10.1.
- v0.5.0 is skipped. develop's unreleased work (AITransport, dialect check, style instructions) is folded into v1; npm stays at 0.4.1.
- Repo: this repo. TS moves to a `legacy` branch; TS files are then dropped progressively from `main` as each Rust surface lands; `main` holds only the minimal maintainable new stack, not two parallel implementations.
- Extensions are agnostic: no third-party eval/check service is a core dependency. Jev ships as an `examples/` exec-check recipe, not a builtin.
- License: Apache-2.0 everywhere.
- Version line: the Rust release continues 0.x; next release is `v0.5.0`, not v1.0.0, signalling the new stack is still maturing.
- Sequencing and extension model follow cauce's v3 approach.

## 2. Lessons imported from cauce v3

1. The golden path against a real provider and a deterministic provider is the first artifact, not the last.
2. Extension tiers ship in order: native, declarative, exec (versioned JSONL child process), QuickJS later.
3. Cassette record/replay makes provider calls deterministic in CI.
4. One binary, XDG dirs, config layering defaults < TOML < env with `${env:VAR}` interpolation.
5. Licensing split: copyleft core, permissive specs and SDKs (cauce: MPL-2.0 / Apache-2.0). intl-ai goes Apache-2.0 everywhere (owner decision, section 1).

## 3. Crate layout

```
crates/
  intl-ai-core        diff, lockfile, flatten/hash, traits (Provider, Transport, Format, Processor, Check), pipeline services (fill, check)
  intl-ai-formats     json, yaml (serde_json, serde_yaml-ng)
  intl-ai-providers   http transport (openai-compatible, anthropic), command transport (AITransport port from develop)
  intl-ai-checks      builtin checks + declarative spec runtime + exec check runtime
  intl-ai-cli         clap binary: fill, check, init, record/replay
  intl-ai-uniffi      (later) UniFFI bindings surface
specs/                declarative check specs shipped with the binary (dialect wordlists etc.)
sdk/python            exec check SDK (later; port cauce_engine_sdk protocol discipline)
```

`intl-ai-core` keeps the hexagonal contract the TS code already declared for this seam: traits are serializable-in/serializable-out; no subprocess types in `core` (command transport lives in `intl-ai-providers`, same carve-out as TS).

File-size discipline (cauce W3-08 rule, also going into AGENTS.md): decompose along privacy boundaries rather than enforcing a per-file cap: `foo.rs` > ~1000 LOC triggers review, > ~1500 a decomposition issue, functions > ~150 get extracted, test modules > ~800 split into focused files; a non-gating LOC/complexity report runs in CI (implementation vs test LOC, largest files/functions) and warns without failing merges. The target is low coupling and easy review, not LOC austerity.

## 4. Distribution

- `cargo-dist` (axo `dist`): GitHub Releases with per-platform tarballs, `install.sh`, Homebrew tap (`sigilco/homebrew-tap`), mise/aqua, winget later.
- npm stays as a shim channel, not the tool itself: `@intl-ai/cli` becomes a wrapper resolving a platform binary via optionalDeps (`@intl-ai/cli-darwin-arm64`, ...), the esbuild/biome pattern. Same for `@intl-ai/unplugin` and `@intl-ai/next`, which become thin spawn wrappers.
- PyPI deferred: no Python-side consumer needs `pip install intl-ai` while brew/install.sh exist. Revisit if a Python SDK for checks lands.
- Container image (`ghcr.io/sigilco/intl-ai`) later for CI-native use.

## 5. Port strategy (adversarial audit, 2026-09-24)

Three sessions audited `packages/api` + `packages/cli` + the shims across main (v0.4.1) and develop (15 unreleased commits): a port advocate, a clean-slate advocate, and a neutral auditor producing a module-by-module truth table. All three converge on the same split; the auditor's phrasing: "A wins the evidence, B wins the architecture; spec the semantics, rewrite the plumbing."

**Clean rewrite in Rust. The carrier of value is a written `specs/` set, not ported code. (Owner decision: NO legacy compat required; the specs are reference knowledge, not compatibility contracts; v1 may redesign any internal surface toward minimal/composable/agent-first/constrained goals.)**

- Of ~3,700 non-test lines, ~65% is TypeScript plumbing with no Rust analogue (zod ceremony, jiti loading, function-typed config fields, barrel files, duck-type guards, the stateful `LockfileManager` class, `Promise`/`mapPool` idioms). Porting it constrains the Rust design and inherits its bugs.
- The load-bearing knowledge is ~350 lines plus ~80 behavioral decisions invisible to spec readers (ARCHITECTURE.md is a stale component diagram; the JSON schema covers config shape only; tests cover ~60% of them). Carried as **specs + data + conformance vectors**, not translated code (§5.1). The auditor's 16-section spec outline maps onto §5.1 and becomes the `specs/` table of contents.
- Coverage is inverted vs need: the most spec-critical surfaces (provider wire shapes, locale file formats) have zero tests, while orchestration is well covered. The spec must come from code, not tests.
- A line-port would also reproduce the fifteen live bugs the audit found (§5.3); several shipped in v0.4.1.
- Auditor's per-module table: PORT-AS-SPEC for diff/lockfile/formats/translator+command-transport semantics/presets/prompts/quality-loop/dialect-wordlist; REWRITE for config loader, schemas, CLI, unplugin/next shims; RE-DERIVE for batch orchestration, check, registries.

### 5.1 Port as spec/data (the hidden-decisions list)

Cannot be re-derived from docs; these get spec pages under `specs/` plus conformance fixtures. With legacy compat dropped, each item is tagged KEEP (external contract or proven semantics worth preserving verbatim) or REDESIGN (internal surface free to simplify under the new goals):

1. **Lockfile semantics**: REDESIGN (new format, no migration): keep only the proven semantics: fail-closed on corrupt, atomic tmp+rename, deterministic sorted entries, schema-version field, `origin`/`quality` record shapes. The `locale||key` composite-key format and v1→v2 migration are dropped; v1 is the sharded TOML design in §5.5.
2. **Diff/hash semantics + flattening coercion table**: KEEP semantics, re-decidable coercions (the `null`→`"null"` leaf coercion is almost certainly a bug to spec away rather than preserve): SHA-1 lowercase hex of the UTF-8 flat source _value_ (the v0.3.0 flat-key bug is the cautionary tale). Flatten coerces everything to strings: numbers → `"5"`, booleans → `"true"`, `null`/`undefined` leaves → literal `"null"`/`"undefined"`, arrays → compact `JSON.stringify`. Flat dot-keys are indistinguishable from nested paths (source `"nav.home"` writes out nested; value-stable, not shape-stable). Missing = `undefined` only; empty string counts as present. Stale only when a lockfile entry exists AND hash differs; keys with no lockfile row are immortal. `extra` keys informational, never fatal, never deleted by fill. Note: the TS `force`-retranslates-everything semantic is REPLACED in v1 by the additive-fill + scoped `--regenerate`/`--include-human`/`--stale` model (§5.6).
3. **Command transport discipline**: KEEP verbatim (safety contract, not compat): `system\n\n---\n\nuser` prompt framing, `promptVia` stdin-vs-argv (crush ignores stdin), never `shell:true`, 300 s timeout + SIGTERM→5 s→SIGKILL, 10 MB stdout cap, stderr preview in errors, stdin always closed, ANSI/VT strip, `extractJsonPayload` fenced-then-balanced-string-aware-brace order. `command.test.ts` cases become protocol conformance vectors.
4. **Agent preset table as data**: KEEP verbatim: `claude -p --dangerously-skip-permissions --output-format text`, `opencode run --auto` (docs claim `--yolo`; wrong), `codex exec --approve-for-me` (incompatible with `--sandbox`), `crush run -q` + argv, `gemini -p "" -y` (empty `-p` keeps prompt on stdin). Re-verify against installed CLIs before shipping.
5. **Prompt contracts as frozen strings**: KEEP (external contract with models): translate system+user prompts (numbered `N. "source" (key: k)` entries, glossary/feedback blocks, `{translations:[{key,translated}]}` contract), judge prompts + `ADVERSARIAL_SYSTEM_PROMPT`, temperatures (0.3 fill / 0 judge), retry scope (transport+parse only; per-key failures terminal), `ErrorType` taxonomy (429-only `rate_limit`), omitted-key → `output_truncated` / judge score-0.
6. **Config contract**: REDESIGN to one constrained schema in the user's format of choice (TOML/JSON/YAML via config-rs, §7): keep resolution rules (`localeDir`/agent `cwd` resolve against the config file's dir), `${VAR}`/`$VAR` interpolation, `command` beats `agent` preset, and the strict-unknown-key posture. The JSON-vs-TS divergences die with the format split. Note for exec-check spec files: the "no arbitrary `command` in data-format files" security boundary stays as a design rule for any drop-in file that could come from a dependency.
7. **Dialect detector**: KEEP: `[A-Za-z]+(?:'[A-Za-z]+)?` word regex, US→american / GB+UK→british region map, case-preserving suggestions, ICU-token exclusion spans, british→american = inverted table first-wins. The MIT wordlist (~1,700 entries) ships as data verbatim.
8. **CLI + report contract**: KEEP semantics (exit codes, concurrency defaults, report shape); flag surface is free to evolve: exit codes 0/1/10, `hasIssues` excludes `extra`, `concurrency` 4 default → 1 for `kind: "agent"`, progress to stdout / per-batch results + failure breakdown to stderr, `.intl-ai/report-<ts>.json` (version 1 shape) written iff failures && !dryRun.
9. **Provider wire quirks**: KEEP (external wire contracts): OpenAI `parseResponse` strips ```fences and requests strict`json_schema` (`additionalProperties:false`everywhere); Anthropic`system`text-block array +`max_tokens`default +`anthropic-version`(see §5.3; current auth is a bug);`modelParams`spread last so user params override;`Authorization: Bearer <resolved key>` always injected.
10. **Retry and error taxonomy**: KEEP: maxRetries default 3 (cap 10 fill / 5 quality), no backoff or jitter, per-attempt 300s cap, every class retried including 401/403. Classification is message-substring matching, order matters: HTTP 429 → `rate_limit`, other !ok → `http`, ENOENT → `spawn_failure`, timeout names/messages → `timeout`, "exited with code" → `process_exit`, JSON/parse → `parse_error`, exact "Empty response from model" → `empty`, else `unknown`. Per-key axis is separate: omitted key → `output_truncated`, processor failure → `validation`; neither retries. `rawResponse` preview = first 500 chars + "..." on parse failures only.
11. **Quality loop contract**: KEEP semantics: enabled iff a `quality` object exists (even `{}`), options.quality replaces config wholesale. Judge: single attempt (no retry), temperature 0, `tierFor` boundaries 0.6/0.8, omitted key → score 0/high/needsReview, judge crash aborts the whole locale. Below-threshold translations still written to file + lockfile quality record; only `failOnLowQuality` blocks shipping. Refill failure keeps last translation, lands in belowThreshold. Refill prompt = judge reason + `type (severity): description` feedback + previous attempt. `kind:"agent"` + quality + no custom assessor → hard error. Judge beats assessor.
12. **Hook contract**: REDESIGN (no function-typed hooks in a static binary): the observable semantics (per-attempt events, `attempts[]` history, model fallback to transport.id) become tracing events + exec-hook payloads. Shims must preserve nonzero exits and the one-fill-per-build invariant.

### 5.3 Bugs found by the audit: fix in v1, do not port

1. **#41 structural**: `lockfileEntryToMap` narrows to `{sourceHash}` so `origin:"human"` is invisible to the diff; `isHumanEdited` has zero callers; `origin:"human"` is never written by any code path; the `--force` flag's documented contract is a lie.
2. **Anthropic auth broken** (shipped in 0.4.1): literal `X-Api-Key: "${apiKey}"` never interpolated; auth accidentally rides `Authorization: Bearer`, which Anthropic's API doesn't use; likely broken against api.anthropic.com; only OpenRouter was live-tested.
3. **`batchSize` ignored on initial translate**: chunked only on refills.
4. **`errors++` drops the error**: per-locale failures (e.g. unreadable file) produce a count with no `failures` entry.
5. **Lockfile last-writer-wins**: `batchedFill` runs N `runFill`s each with its own `LockfileManager` doing load-then-rewrite; concurrent locales clobber each other. v1: one writer behind a mutex.
6. **`onProgress` >100%**: cumulative numerator over per-locale denominator.
7. **`unflattenObject` remap quirk**: dangerous mid-path segment truncates but still writes (`a.__proto__.b` → `a.b`); drop dangerous keys instead. The prototype-pollution guard itself has no Rust analogue.
8. **Judge `needsReview` hardcodes 0.8** vs the configured threshold; plus fake `TranslationResult` stuffing (`key: reason`, `translated: score`) to fit the hook shape.
9. **Quality path writes `model: undefined`** under `kind:"agent"` vs `modelLabel` on the normal path.
10. **Dead exports**: `getNestedValue`/`setNestedValue` (the machinery behind the v0.3.0 bug), `TranslationStaleEntry`, quality aliases, `defineConfig` (LSP-only identity fn).
11. **unplugin swallows `IntlAiQualityError`**: `buildStart` wraps everything in a catch-all that downgrades errors to warnings, so `quality:true` + `failOnLowQuality` can _never_ fail a build. The spawn-shim design fixes it naturally (nonzero exit propagates), but the shim must preserve exit codes.
12. **Command transport: stderr uncapped**: stdout is capped at 10MB but stderr buffers unbounded; a verbose or hostile agent can OOM the host. v1 spec must set a stderr cap.
13. **Judge fetch has no timeout**: translator caps at 300s; judge does not (inconsistent with its own single-attempt semantics).
14. **Config-path divergences**: CLI never discovers `intl-ai.config.ts` by default (`.json` only); JSON-vs-TS processor default produces different prompt hints (§5.1.6). Collapse in the TOML contract.
15. **Docs rot**: ARCHITECTURE.md's `LocaleFormat`/`TranslationHook` signatures are stale vs develop (missing `onAttemptFailure`); observability.md documents 3 of 4 hooks; providers.md claims temperature is configurable (it's hardcoded). The `specs/` doc set replaces these as source of truth.

### 5.5 Lockfile design: as a DB (Sept 2026 survey)

**Two kinds of state, two different treatments.** DX tooling splits cleanly: committed shared truth (Cargo.lock, pnpm-lock.yaml, Package.resolved) vs ephemeral local incremental state (tsbuildinfo, per-file signature hashes, `useFileVersionAsSignature` laziness, explicitly "safely deleted", gitignored; Nx/Turbo/Bazel caches, content-hash-keyed, gitignored, optionally remote-cached). intl-ai's lockfile is mostly the first kind: `origin`, `quality` records, and which keys have AI output are non-recomputable data that must sync across teammates via git. But it borrows the second kind's speed tricks via a gitignored stat-cache.

**Format survey** (Nesbitt's lockfile tradeoff survey + the tools' own redesigns): Cargo.lock/uv.lock = TOML flat `[[package]]` blocks, sorted, schema-version-for-format-changes only; pnpm-lock.yaml v6 was redesigned explicitly for merge-friendliness; bun.lock is JSONC _deliberately_ for trailing commas; package-lock.json (nested JSON) is the worst merger, no trailing commas means every added entry touches 2+ lines; go.mod+go.sum split requirements/verification (line-based diffs best but can't hold structured metadata); Gemfile.lock nests (ripples). Convergent practice: mergeability > compactness; flat over nested; deterministic sorted order; schema version for format changes only (never tool version, cf. Bundler's `BUNDLED WITH` friction); self-contained; minimal extrinsic metadata; atomic writes.

**Decision: a sharded lockfile directory, `intl-ai.lock.d/<locale>.toml`** (one flat TOML file per locale, `version = 1` header, `[entries."<key>"]` blocks sorted by key). Rationale against the user's "lockfile as DB" criteria:

- _Snappy when it grows_: per-locale shards bound file size (the growth axis is keys-per-locale, not total keys); only dirty shards are parsed+rewritten; an in-memory index handles the run. A gitignored stat-cache (`.intl-ai/cache.json`: path → mtime+size → sourceHash) skips re-hashing unchanged locale files, the tsbuildinfo `useFileVersionAsSignature` / git-index trick. Escape hatch if profiling shows pain at 100k+ keys-per-locale: a gitignored SQLite index in front, text shards stay the source of truth.
- _Consistent across runs/builds/devices_: pure functions of the committed shard contents + current source files; no machine-local state in the mergeable surface (the stat-cache never leaves the box); atomic tmp+rename per shard; fail-closed on corrupt (never silently regenerate an unparseable shard, `origin: "human"` data is unrecoverable).
- _Shareable across teammates_: committed to VCS. Cross-locale merges structurally cannot conflict (different files); same-locale merges see one-sorted-block-per-key diffs with TOML trailing commas, the best case of any format surveyed. Deterministic ordering means identical content → identical bytes, so diffs are meaningful.
- _Agent-first auditable_: text, sorted, one key per block, comments allowed (`origin = "human"  # corrected by @x, ticket 1234`), `git diff` shows exactly which keys changed.

Deliberately NOT: SQLite/binary as committed truth (unmergeable, unauditable); single nested JSON (worst diffs); embedding hashes-of-everything (extrinsic metadata ripples); tool-version stamps (Bundler's friction); a local-only cache for lock data (origin/quality can't be regenerated).

**Hard properties (owner checklist), and how each is guaranteed:**

- _Deterministic_: sorted keys per shard, one serialization profile (header + entry blocks in fixed field order); identical content ⇒ identical bytes; `lockfile fmt` is a fixed point.
- _Idempotent_: a shard is only written when its serialized bytes differ from on-disk (no mtime bump, no dirty git state); fill/check are pure functions of committed shards + current sources.
- _Normalization_: `intl-ai lockfile fmt` canonicalizes ordering/whitespace/header; the single serializer owns field order on every write, no hand-emitted fragments.
- _Integrity_: strict typed parse; `version` header checked; fail-closed on corrupt (never overwrite an unparseable shard, `origin:"human"`/`reviewed` data is unrecoverable); atomic tmp+rename; `lockfile check` validates offline.
- _Git-friendly/mergeable/no binary_: text TOML only; per-locale shards cap conflict surface at one file per locale; one sorted block per key → one-block diffs; deterministic bytes → meaningful `git diff`/`merge`; dedicated `lockfile merge` command for conflict resolution.
- _Lightweight staleness_: stat-cache (`.intl-ai/cache.json`, gitignored: path → mtime+size → source_hash) skips re-hashing unchanged sources (tsbuildinfo `useFileVersionAsSignature`/git-index trick); staleness itself is an O(1) stored-vs-current hash compare.
- _Format versioning_: integer `version` per shard, bumped only for breaking changes (Cargo's version-for-schema-changes-only rule, never the tool version).
- _Forward-compatible semantics_: additive-only field evolution, new optional entry fields never force a bump. Readers MUST ignore unknown entry fields; writers MUST refuse a shard whose `version` exceeds their max (fail-closed, no silent downgrade); same-version unknown fields are preserved verbatim through read-modify-write (passthrough map), so a newer binary's fields survive an older binary's rewrite.

Migration: none needed, no legacy compat. A `intl-ai migrate` command that reads a v2 `intl-ai.lock.json` and writes shards is a cheap nice-to-have for the team itself, not a compat contract.

The entry shape carries what the HITL survey (§5.6) requires: `value` (last AI-written value, gettext `#| msgid` precedent: check needs to show "file differs from what AI produced" and a hash alone can't diff), `source_hash`, `origin` (ai|human), `reviewed` (bool, orthogonal to origin), `model`, `updated_at`, plus `quality` records. Direct lockfile edits are allowed but positioned as machine-managed (rushstack bulk-suppressions precedent: document it, optionally CODEOWNERS it); `intl-ai lockfile fmt`/`merge`/`check` normalize and resolve conflicts (betterer precedent, a dedicated merge command for a machine-owned committed file).

### 5.6 Human-origin model + fill/check semantics (HITL survey, 2026-09-24)

Survey of TMS status models (Crowdin, Phrase TMS/Strings, Lokalise, Smartcat, Weblate, Localazy, Tolgee, XLIFF 2.0), CMS AI-suggestion flows (Contentful, Sanity, DatoCMS, GitBook), and code-assist/baseline precedents (dependabot, renovate, eslint suppressions, betterer, cargo update, gettext msgmerge, i18next-parser, Lingui, cspell). Report: `.agents/` survey doc `hitl-origin-mechanisms.md`.

**Industry norm confirmed**: every serious TMS is additive-only by default; Smartcat has no overwrite option at all; Crowdin's middle tier "Replace auto-generated (keep human)" is exactly `fill --regenerate`. Stale is always a flag, never an auto-rewrite (Localazy `source changed`, Phrase unverified-on-source-change, gettext `fuzzy`).

**Status model: two orthogonal fields, not one enum**: `origin: ai|human` (authorship) × `reviewed: bool` (readiness). Crowdin stores `is_pre_translated` + `is_approved`; Tolgee provider-indicator + reviewed; XLIFF `state` + `subState`. No third tier in v1 (Weblate's `approved` only matters with role permissions a file-based CLI doesn't have). `reviewed` resets on any value edit (Phrase's "modified ⇒ unverified" rule).

**Human-owned = positional rule**: if the file value differs from the recorded lockfile `value`, a human edited it → `origin = human`, and the recorded `value` stays as provenance/diff base. This is exactly Crowdin's "Machine Translations" filter ("translated without changes") and Tolgee's indicator-clear-on-edit. Guard: skip keys fill wrote this run (`written_this_run`) so the tool never self-marks. Escape hatch `intl-ai mark <key-spec> --origin human` for the case the rule can't see (human restores the exact AI text). Adoption: on first run, keys with values but no lockfile entry → `origin: human` (never claim authorship of text the tool didn't produce). Rejected: git-blame-derived origin (breaks on reformat commits, the `.git-blame-ignore-revs` problem).

**fill semantics**: additive-only by default; regeneration always scoped and per-invocation (Renovate's sticky rebase-checkbox clobber bug is the lesson: never persist an override in config):

```
intl-ai fill                              # only keys with NO value
intl-ai fill --keys "auth.*"               # scope: dotted-key globs, not line ranges (they rot); cargo update -p precedent; also --keys-file
intl-ai fill --keys <spec> --regenerate   # overwrite AI-owned values only
intl-ai fill --regenerate --include-human # overwrite everything scoped; prints count of human keys affected
intl-ai fill --stale                      # re-fill AI-owned keys whose source_hash changed
```

**Stale is a check finding, not a rewrite.** A stale human key is never auto-regenerated; the human decides whether to re-edit or `intl-ai mark --origin ai` it back to AI stewardship. Stale AI keys are reported by `check` and fixed by `fill --stale`.

**check semantics**: same gates on human and AI values (Phrase: unverified still ships, but is still checked; human text isn't exempt from dialect/ICU/judge). Findings: `stale`, `invalid`, `modified` (transitional, reconciles to origin:human), `unreviewed` summary counts. `--origin` filter for CI (enforce "no invalid AI strings" while tolerating human debt); `check.fail_on: [stale, invalid]` config knob; whether `unreviewed` gates is opt-in.

**Command surface** (grammar: verbs = actions, noun-groups = state surfaces):

```
intl-ai init                    # scaffold intl-ai.toml + locale dir detection (<5-min integration goal)
intl-ai fill    [--locale L] [--keys GLOB|--keys-file F] [--stale] [--regenerate] [--include-human] [--dry-run]
intl-ai check   [--locale L] [--origin ai|human|all] [--fail-on stale,invalid,...] [--format json]
intl-ai mark    <spec> --origin ai|human     # single verb; --origin ai reverses it, no `unmark`
intl-ai review  <spec>                       # sets reviewed=true (renamed from `verify`: matches the field, avoids colliding with `check`)
intl-ai unreview <spec>
intl-ai lockfile fmt | merge | check          # normalize / resolve conflicts / validate machine-owned state
intl-ai config validate [--format json]
intl-ai migrate                               # optional 0.4.x helper (nice-to-have, not a compat contract)
```

Verb rationale (challenged 2026-09-24): `fill` stays; it honestly names the additive default (fill gaps, never rewrite) and is established project vocabulary; runner-up `translate` is the domain verb users will guess first (cheap alias later if they trip) but says nothing about the additive contract; `sync` wrongly implies bidirectional, `extract` is reserved for source-string extraction. `check` stays; `cargo check`/`tsc --noEmit` precedent, reports findings without writing; `lint` is the strongest alternative (biome/oxlint family) but narrower, staleness is a state, not a rule violation. `verify` → `review` (matches `reviewed`, dodges the check-collision). `--format json` on every read command (agent-first output contract). `stale` standalone alias dropped; `check` covers it (minimal surface). `status` (inventory counts by locale/origin/reviewed) deferred; nice-to-have, not core. Overrides stay per-invocation flags, never config (Renovate clobber lesson).

## 6. Check tiers (the extension model)

Mapped from cauce's engine ladder, smallest sufficient thing first:

1. **Native checks** (compiled in, `Check` trait, all agnostic): `icu`, `placeholder-parity`, `dialect:<locale>` (wordlists in `specs/`), `judge` (score via whichever provider is configured). Nothing vendor-specific ships in core; Jev and friends live in `examples/checks/` as exec recipes (e.g. `examples/checks/jev/` wrapping the System One HTTP API with `TYPESAFE_API_KEY`).
2. **Declarative specs** (YAML, drop-in like cauce `engines/*.yaml`): rule checks a user writes without code: `forbidden_terms`, `required_terms`, `regex`, `length_ratio`, wordlist refs. The colleague's en-US need is satisfiable here or via the `dialect` builtin.
3. **Exec checks**: `[[check]]` config entry spawning a command speaking one JSONL request/response pair per run (batch, not per-key). Versioned protocol `v: 1` from day one; the cauce exec protocol (optimistic version negotiation, warm-process rules) is the reference. A Python SDK ships when someone other than us writes the third exec check.
4. **QuickJS checks** (`rquickjs`, `checks/<id>.js`): deferred stub, same trigger condition as cauce: needed when declarative can't express the logic and a subprocess is too heavy.

## 7. Integration surfaces

- **CLI-first**: every stack integration is "run `intl-ai fill` in a build step": Gradle task, Xcode script phase, Fastlane, npm script, CI job.
- **JS shims**: `@intl-ai/unplugin` / `@intl-ai/next` spawn the binary on `buildStart`; they lose the runtime-agnostic library and become ~100-line wrappers. Bundler users still need Node (the bundler does), but the tool itself no longer does.
- **UniFFI**: later, only if a host wants in-process embedding rather than CLI invocation. Also the answer to "library on top of intl-ai": a UniFFI surface plus stable `--format json` output and `--config -` stdin make intl-ai usable as a build tool's engine, not just a CLI.
- **Config** (`config-rs` 0.15, standard layered-config crate, Apache-2.0, actively maintained): users configure in **their format of choice or their stack's idiom** (owner decision): canonical `intl-ai.toml` plus `intl-ai.json` / `intl-ai.yaml`, all deserializing into one typed serde contract with `deny_unknown_fields`. Code-based config is dropped by design (no eval runtime in a static binary); the flexibility it bought moves to exec checks, `extends`, and UniFFI.
  - Format data (Sept 2026 survey): web tools split between JSONC + JSON Schema (biome, oxlint, turbo, tsconfig) and code configs (vite, eslint flat, next); mobile splits between YAML (pubspec, xcodegen) and code (Gradle KTS, Fastfile, Podfile); Rust-native tools are uniformly TOML (Cargo, mise, uv, cargo-dist, git-cliff, typos). Tauri, the closest precedent (a Rust binary serving all ecosystems), ships JSON default with JSON5/TOML options.
  - Type-safe tooling: `intl-ai config validate` subcommand + one generated JSON Schema published to SchemaStore, serving JSON and YAML arms in editors directly and the TOML arm via Taplo schema association.
  - Layering: defaults < `extends` chain < file < `INTL_AI_*` env overlay (config-rs `Environment` source) < CLI flags. `${env:VAR}`/`${env:VAR:-d}`/`${env:VAR:?}`/`${file:PATH}` in-string interpolation (cauce syntax) stays custom on top; config-rs' env source overrides keys, it does not interpolate inside values.
  - Extends: `extends = "./base-intl-ai.toml"` (string or list) merges shared org/team configs, covering the "build an i18n lib on top of intl-ai" and monorepo cases.

## 8. Testing

- Cassette record/replay (cauce `replay` engine pattern): a `replay` transport serving recorded provider responses; golden-path e2e never touches a real API.
- Live integration tests (the vitest integration infra on develop) become cassettes plus a nightly live-smoke job, not a merge gate.
- `intl-ai check --self-test` for declarative specs (cauce's spec self-test idea): a spec ships with clean/broken fixtures.

## 10. Language assessment (Go / Zig / alternatives vs Rust)

The tool's shape: single static CLI, JSON/YAML IO, HTTP to LLM APIs, subprocess spawning, ICU parsing, config, then UniFFI bindings and a JS sandbox tier.

| Candidate                                                     | Fit                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | Verdict                                                                                                              |
| ------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| **Rust**                                                      | UniFFI is Rust-only: generated Kotlin/Swift/Python bindings vs hand-written shims everywhere else. `formatjs_icu_messageformat_parser` gives JS-parity ICU ASTs; ICU4X exists if MF2 is ever wanted. `rquickjs` is exactly cauce's deferred sandbox pick. cargo-dist covers brew/mise/install.sh. Second Rust core in the org: cauce's exec protocol, cassette infra, and CI patterns transfer directly. Cost: slower compile/iteration; contributor friction (borrow checker) for an OSS tool. | Chosen.                                                                                                              |
| **Go**                                                        | Best cross-compile and binary distribution ergonomics of the three (goreleaser), fastest iteration, trivial contributor on-ramp. But UniFFI is Rust-only: mobile/desktop bindings would mean hand-written C-ABI shims per language (gomobile is a weaker, Go-side-API story). ICU MessageFormat validation would be hand-rolled (`x/text` doesn't parse MF1). JS sandbox = goja (pure-Go interpreter; viable but heavier than rquickjs for this use).                                           | Runner-up. Correct only if UniFFI is permanently out of scope and integrations stay CLI/exec/YAML forever. It isn't. |
| **Zig**                                                       | Smallest binaries, ideal C-ABI story, `zig cc` cross-compile is excellent. But every layer needs building: no UniFFI, no LLM/HTTP client ecosystem at Rust/Go maturity, no ICU parser, QuickJS would be hand-embedded via C. For an integration-breadth product the ecosystem tax compounds: it's the right language for foundational infra, not for a glue-and-shims CLI maintained by a small team.                                                                                           | Wrong shape for this product.                                                                                        |
| Kotlin Multiplatform / .NET AOT / Nim / Crystal / Bun compile | Each fails a hard requirement: KMP-Native isn't CLI-native and binaries are heavy; .NET AOT has no mobile-binding generation and embedding means custom C ABI anyway; Nim/Crystal have Zig's ecosystem problem minus the momentum; `bun build --compile` keeps the runtime-weight problem the migration exists to escape (~50MB+ binaries).                                                                                                                                                     | Rejected.                                                                                                            |

The decision hinges on one axis: **is per-language binding generation (UniFFI) in scope?** With it, Rust is the only option. Without it, Go is a credible runner-up on simplicity alone. UniFFI was named in the goals, so: Rust.
