# intl-ai Kotlin packages

Consumable Kotlin artifacts for the UniFFI bindings generated by
`crates/intl-ai-uniffi`. Two modules:

| Module           | Artifact                                 | Contents                                                                                       |
| ---------------- | ---------------------------------------- | ---------------------------------------------------------------------------------------------- |
| `intlai`         | `io.github.sigilco:intlai` (JAR)         | Generated bindings plus the native cdylib for the host platform (Linux, macOS, Windows JVMs)   |
| `intlai-android` | `io.github.sigilco:intlai-android` (AAR) | Generated bindings plus `libintl_ai_uniffi.so` for `arm64-v8a`, `armeabi-v7a`, `x86`, `x86_64` |

Both wrap the `uniffi.intl_ai_uniffi` bindings (`IntlAi` object, `fill`,
`check`, `status`, and the `*Json` variants) without copying them: the Gradle
modules compile the checked-in `.kt` output under
`crates/intl-ai-uniffi/bindings/` directly.

## Requirements

- JDK 17 or newer.
- Cargo and Rust stable (the Gradle tasks invoke `cargo` on the repo workspace).
- For `intlai-android`: Android SDK with platform 36, build tools 36.0.0, and
  NDK `27.2.12479018`, plus `cargo-ndk` (`cargo install cargo-ndk`) and the four
  Android Rust targets (`rustup target add aarch64-linux-android
armv7-linux-androideabi i686-linux-android x86_64-linux-android`).
  Point Gradle at the SDK via `sdk.dir` in `local.properties` or the
  `ANDROID_HOME`/`ANDROID_SDK_ROOT` environment variable.
- For `intlai`: nothing beyond cargo; the module detects the host platform and
  embeds the matching `libintl_ai_uniffi`.

## Build

```sh
./gradlew build                 # both modules, including the JVM test
./gradlew :intlai:build         # JAR only (host native + smoke test)
./gradlew :intlai-android:assembleRelease   # AAR only (all four ABIs)
```

Outputs:

- `intlai/build/libs/intlai-<version>.jar`: bindings plus
  `libintl_ai_uniffi` under `/<jna-platform>/` so JNA extracts it from the
  classpath at first use.
- `intlai-android/build/outputs/aar/intlai-android-release.aar`: bindings plus
  `jni/<abi>/libintl_ai_uniffi.so` for every ABI.

Both modules declare `net.java.dev.jna:jna:5.18.1` (AAR variant on Android) and
ship Maven publications, so `./gradlew publishToMavenLocal` installs them as
`io.github.sigilco:intlai:0.7.0` and `io.github.sigilco:intlai-android:0.7.0`.

## Consume

Android:

```kotlin
dependencies {
    implementation("io.github.sigilco:intlai-android:0.7.0")
}
```

Desktop JVM:

```kotlin
dependencies {
    implementation("io.github.sigilco:intlai:0.7.0")
}
```

```kotlin
import uniffi.intl_ai_uniffi.IntlAi

val api = IntlAi.fromConfigString(config, ConfigFormat.TOML, workingDir)
val report = api.check(CheckOptions(/* ... */))
```

Every exported call is synchronous (the transport layer blocks on HTTP or
subprocess). Call from a background dispatcher (`Dispatchers.IO` on Android or
Kotlin coroutines, a worker thread on the JVM), never the main thread.

## Native library resolution

- JVM: JNA searches `jna.library.path`, then the classpath at
  `/<platform-prefix>/libintl_ai_uniffi.so`. The bundled copy covers the
  platform the JAR was built on; point `jna.library.path` at a custom build or
  set `uniffi.component.intl_ai_uniffi.libraryOverride` to override the name.
- Android: the app bundles `jni/<abi>/libintl_ai_uniffi.so` from the AAR and the
  runtime loads it automatically.

Cross-building a different desktop target:

```sh
./gradlew :intlai:build \
  -PintlAiRustTarget=aarch64-apple-darwin \
  -PintlAiJnaPrefix=darwin-aarch64
```

(requires the Rust target and linker for that triple).

## Regenerating bindings

The committed `.kt` file is the source of truth for the package. After changing
the exported Rust API:

```sh
./gradlew generateKotlinBindings
# or: crates/intl-ai-uniffi/scripts/generate-bindings.sh
```
